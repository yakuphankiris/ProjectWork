# Smart Parking Garage Management System

## My interpretation of the brief
The project is a database-centered parking garage management system with a simple web interface. The database must model parking spaces, customers, vehicles, reservations, parking events, tariffs, payments, subscriptions, and maintenance. Its main responsibility is to enforce business rules, including preventing overlapping reservations, maintaining consistent parking-space states, and calculating fees. The web interface demonstrates these functions through availability searches, reservation management, occupancy information, and basic statistics. Transaction handling, concurrent access, and measured query optimization are central to the project.

## Why I am a good fit for this project
I have previously completed a similar project and am currently working on another related project. This makes the topic familiar and gives me a practical starting point. I have intermediate experience with C#, Microsoft SQL Server, and the .NET Framework, and I believe I can use this knowledge effectively in this project. I am particularly interested in developing my database skills further by studying how reservations and other operations can remain reliable when several users access the system at the same time.

## Relevant experience and background
My previous and current project work has given me experience with C#, the .NET Framework, and Microsoft SQL Server. I would draw on this background when connecting the application to the database and implementing the supporting application layer. I also see this project as an opportunity to deepen my understanding of database-side business logic, transaction isolation, locking, and performance analysis.

## Proposed approach
I would use Microsoft SQL Server and T-SQL for the database, with a C#/.NET service layer and a simple web interface. I would first design a schema in at least third normal form, covering the required entities in at least twelve related tables. Essential rules would be enforced through constraints, stored procedures, functions, and triggers where justified.

I would then implement the reservation, entry, exit, and fee-calculation workflows. To prevent double booking, I would compare at least two transaction or locking approaches under concurrent requests. After establishing correct behavior, I would generate reproducible test data and compare query performance before and after indexing and optimization. The web interface would use the database functions through the service layer.

## Initial plan
1. Define the business rules, reservation workflow, parking-space states, and fee-calculation assumptions.
2. Write the specification and design the relational schema, constraints, and database procedures.
3. Implement and test reservations, entries, exits, fee calculation, and concurrent access; compare two transaction or locking approaches.
4. Generate at least 100,000 reservation and parking events and develop at least ten complex SQL queries.
5. Measure and optimize at least five queries using execution plans, SET STATISTICS IO, and SET STATISTICS TIME.
6. Build the web interface and test the complete workflows, including invalid and unauthorized operations; document setup and results.
