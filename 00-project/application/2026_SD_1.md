# Camera-based book cataloguing mobile application with a web collection viewer

## My interpretation of the brief
The project combines a mobile application for adding books with a web application for browsing a personal collection. Users scan an ISBN barcode, review details retrieved from an external book data source, and correct or complete them before saving. If a barcode is missing or unreadable, AI-assisted extraction from a photograph of a single book cover suggests the visible title and author. Manual entry must remain available. The system must also distinguish works, editions, and owned copies, preserve the source of individual fields, support reversible merges, and provide persistent storage and documented JSON export.

## Proposed approach
I would start with an ASP.NET Core Web API and Microsoft SQL Server for shared storage. Before selecting the mobile technology, I would compare native, cross-platform, and mobile-browser approaches and verify camera access on a real device. I would also evaluate book data sources for usage conditions, request limits, and Hungarian and foreign-language coverage.

The first complete workflow would cover ISBN scanning, validation, external lookup, user review, saving, and web viewing. I would then add cover-based extraction using OCR with an LLM or an image-capable model. Extracted values would be schema-validated, marked with their source and uncertainty, and presented for review without inventing publication details that are not visible on the cover.

I would implement a separate edition-resolution component that normalizes records and ranks candidates using multiple signals. It would preserve field-level provenance, distinguish editions and owned copies, and support merge previews and undo. JSON export and validated import would support data portability and repeatable processing without unintended duplicate copies.

## Initial plan
1. Write the specification, compare mobile approaches and book data sources, and design the data model and versioned JSON format.
2. Implement the API, persistent storage, manual entry, and an ISBN-scanning prototype on a real mobile device.
3. Complete the capture-to-web workflow, including editable records, notes, storage locations, search, filtering, and deletion.
4. Add cover-based extraction with output validation and manual fallback; compare it with basic OCR using separate, manually checked test photographs.
5. Implement edition ranking, duplicate warnings, provenance, and reversible merges; compare ISBN-only matching with multi-field resolution and assess the contribution of each signal.
6. Test repeated imports and interrupted saves, add automated checks for core rules, and evaluate identification accuracy, false merges, correction effort, entry time, latency, cost, and export completeness.
