# Design and Performance Optimization of a Relational Database for an Electric Vehicle Charging Network with AI Support

## My interpretation of the brief
The project focuses on designing and implementing a relational database for an electric vehicle charging network and evaluating its performance with realistic, reproducible test data. The model must cover charging stations, charging points, users, vehicles, reservations, charging sessions, consumption measurements, tariffs, payments, and technical events. The main work involves enforcing data integrity, developing complex SQL queries, analyzing execution plans, and measuring the effects of indexing and query optimization. AI-generated suggestions must also be reviewed and compared with independently developed solutions. A complete management application is outside the mandatory scope.

## Why I am a good fit for this project
During my internship, I developed a database-backed warehouse management system (WMS). Although its business domain was different, this experience gave me practical knowledge of relational data modelling, database integration, and communication between an application and a database. I also have intermediate experience with C#, Microsoft SQL Server, and the .NET Framework, which provides a useful foundation for this work. I am very enthusiastic about taking on this project because it would allow me to apply my existing knowledge to a larger database-focused problem while developing new skills in performance analysis, query optimization, and AI-assisted development.

## Relevant experience and background
My previous and ongoing project work has given me experience with C#, the .NET Framework, and Microsoft SQL Server. The WMS project made database-backed systems familiar to me and provides a useful starting point for the proposed work. I expect to use my SQL Server knowledge for the database implementation and my C#/.NET background to develop test-data generation and performance-measurement tools. The project would allow me to build on this experience while learning more about execution plans, large datasets, and systematic optimization.

## Proposed approach
I would use Microsoft SQL Server and T-SQL. I would first design a schema in at least third normal form with at least ten related tables covering the required charging-network entities, with appropriate keys, referential integrity, important business constraints, and database-side business logic. I would then develop a C# tool that uses a fixed seed and documented parameters to generate reproducible test data and run repeatable performance measurements under consistent conditions.

I would create at least ten complex SQL queries covering multi-table joins, aggregation, time-interval searches, subqueries or CTEs, and window functions. For at least five selected queries, I would record the Actual Execution Plan, execution time, and I/O statistics before optimization by using SET STATISTICS IO and SET STATISTICS TIME. I would then compare at least two query or indexing optimization approaches, including query rewrites and simple, composite, and filtered indexes where appropriate. I would repeat the measurements for the same queries after optimization and quantitatively evaluate the results and changes in their execution plans.

For at least three selected queries, I would obtain AI-generated optimization or indexing suggestions, review their correctness and executability, and measure their performance against my independently developed solutions. AI-generated SQL, T-SQL, or DDL statements would always be reviewed before execution, and the comparisons would verify that the queries continue to return correct results.

As an optional extension after completing the core database and performance work, I would like to explore integrating a large language model (LLM) to support the interpretation of charging-usage statistics. I have not yet decided on the exact implementation, but one idea is to record vehicle brands and models alongside charging-session duration, average or maximum charging power in kilowatts (kW), and total energy consumed in kilowatt-hours (kWh). SQL queries or the C# component would calculate the statistics, while the LLM could summarize the results in natural language and suggest patterns for further investigation. Its interpretations would be checked against the underlying data. This extension would give me an opportunity to learn practical LLM integration and develop skills in data analysis alongside the main database work.

## Initial plan
1. Define the charging-network processes, data-model assumptions, and measurement methodology.
2. Write the specification and implement the normalized schema, constraints, and at least one business-logic stored procedure or function.
3. Generate at least 100,000 charging sessions and one million timestamped measurement or status records reproducibly.
4. Develop at least ten complex SQL queries covering multi-table joins, aggregation, time-interval searches, subqueries or CTEs, and window functions. For at least five selected queries, record baseline measurements using the Actual Execution Plan, SET STATISTICS IO, and SET STATISTICS TIME.
5. Apply and compare at least two query or indexing optimization approaches, including simple, composite, and filtered indexes where appropriate. Repeat the measurements for the same five queries, quantitatively compare the results before and after optimization, and interpret changes in their execution plans.
6. Obtain AI-generated optimization or indexing suggestions for at least three queries, verify their correctness and executability, compare their measured performance with my own solutions, and document the results, limitations, and reproduction steps.
7. If time permits after completing the core requirements, prototype the optional LLM integration for interpreting charging-usage statistics and assess its usefulness and limitations.
